# TBB-I18N-001 — Localization, regional behavior, and accessible presentation

## Intent

Make TBB natural and safe to use in supported languages and regions without allowing device settings to alter financial meaning.

## Scope

Initial shipped languages are English and Spanish, including tested behavior for `en`, `en-US`, `es-MX`, `es-419`, and an unexpected locale fallback.

## Rules

- Product strings are localized through Apple-native localization catalogs. User-created content is never machine-translated by TBB.
- Dates, decimal separators, currency formatting, first weekday, and 12/24-hour presentation follow the user’s locale preferences where appropriate.
- A budget has an explicit time zone and configurable period-start rule. Device time-zone changes must not move an existing transaction into a different budget period.
- The stored financial model remains locale-independent: ISO currency code, integer minor units, ISO-8601 instants, explicit time zone, and versioned schemas.
- Text expansion, bidirectional layout readiness, VoiceOver labels, Dynamic Type, Reduce Motion, high contrast, and non-color-only state are part of every localized flow.
- Translation fallback is deterministic: exact locale → base language → development region → Base → first available → main bundle.

## Acceptance criteria

- Given a user switches between English and Mexican Spanish, when viewing an unchanged budget, then text and presentation localize without changing financial totals, periods, or stored values.
- Given a transaction near midnight and a device time-zone change, when the dashboard is refreshed, then the assigned budget period remains stable under the budget-space rule.
- Given a large accessibility text size or Spanish text expansion, when navigating key iPhone, iPad, and Watch flows, then labels remain understandable and controls remain operable.
- Given a missing translation, when the app resolves a string, then a safe deterministic fallback appears without a fatal assertion.
